Pipeline MLOps

Du notebook au service déployé, reproductible

Défiler

Un modèle qui marche sur mon ordinateur ne sert à personne. Ce projet installe la discipline : données versionnées, expériences tracées, un service qui se reconstruit tout seul à chaque commit.

Mon rôle

Mise en place complète du pipeline, du versionnage des données au déploiement cloud.

01

Quatre étapes, un graphe

prepare → train → evaluate → serve, décrits dans dvc.yaml avec leurs paramètres. DVC ne relance que ce qui a changé ; les données et modèles sont stockés sur Google Cloud Storage ; chaque entraînement est tracé dans MLflow.

  • DVC pipeline et remote GCS
  • MLflow tracking
  • Paramètres centralisés (params.yaml)
02

Livrer automatiquement

Service FastAPI conteneurisé avec Docker, pipeline GitHub Actions qui reproduit le pipeline, évalue, et déploie sur Google Cloud avec les secrets du dépôt.

  • Dockerfile
  • CI/CD GitHub Actions
  • Déploiement Google Cloud

Ce que ça a donné

  • 4étapes de pipeline reproductibles
  • 1commande pour tout relancer : dvc repro
  • 0étape manuelle entre le commit et le déploiement
